# AGENTS.md

A [Prettier](https://prettier.io/) plugin that formats the Motoko smart contract language, plus a standalone `mo-fmt` CLI.

## Build, test, format

Run from the repository root:

- Build: `npm run build` (runs `build:wasm` then `build:ts`). Requires `wasm-pack` and a Rust toolchain to compile `wasm/`.
- Build TypeScript only: `npm run build:ts` (outputs to `lib/`).
- Test: `npm test` (builds the nodejs wasm package, then runs Jest). Use `npm run test:quick` to run Jest without rebuilding wasm.
- Format: this repo is formatted with Prettier; settings are in `.prettierrc`. Run `npx prettier --check .` / `npx prettier --write .`.

The `mo-fmt` package has its own scripts under `packages/mo-fmt` (e.g. `npm --prefix packages/mo-fmt run package`).

## Test prerequisite

`tests/compiler.test.ts` reads Motoko sources from a sibling checkout at `../motoko` (relative to the repo root). CI clones it with:

```sh
git clone https://github.com/dfinity/motoko.git ../motoko --depth 1
```

Clone it the same way before running the full test suite locally, or those tests will find no files.

## Layout

- `src/` — plugin source. `src/parsers/motoko-tt-parse` parses; `src/printers/motoko-tt-ast` prints; `src/environments` holds the node and web entry points.
- `wasm/` — Rust crate wrapping the `motoko` parser, compiled to WebAssembly via `wasm-pack`.
- `packages/mo-fmt` — the standalone CLI package, published separately.
- `tests/` — Jest tests. `tests/test-webapp` is a browser test fixture.

## Conventions and gotchas

- `wasm/pkg/` is generated by `wasm-pack`; never hand-edit it. `lib/` (TypeScript build output) and `wasm/target/` are also generated and git-ignored.
- Prettier config (`.prettierrc`): single quotes, semicolons, 4-space tabs, `trailingComma: all`.
- Rust pins are exact for some crates in `wasm/Cargo.toml` (e.g. `wasm-bindgen =0.2.99`, `serde-wasm-bindgen =0.6.5`); keep them exact.
- `.npmrc` sets `min-release-age=7`, enforcing a 7-day minimum age for installed dependency releases.
- Jest runs with `--experimental-vm-modules` (see the `test:quick` script); use that flag if invoking Jest directly.
- CI (`.github/workflows/tests.yml`) runs the build and tests on Node 18, 20, and 22.
- A push to `main` that changes `packages/mo-fmt/package.json` triggers the release workflow, which tags and publishes `mo-fmt` binaries.
