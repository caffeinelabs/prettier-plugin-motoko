# Formatter rework: implementation plan

This turns [formatter-plan.md](formatter-plan.md) into work. The grammar step is done: `tree-sitter-motoko` 0.2.0 is on npm (2026-09-23) and parses both the legacy and the moc 2.0 syntax. The rest of the repo gets rebuilt. Nothing in the current engine, tooling or dependency set is kept for its own sake.

Two deliverables:

1. **A formatter** on the tree-sitter CST. Default mode `preserve` changes layout only.
2. **A migration tool**: `motokoSyntax: "moc2"` in the plugin and `mo-fmt migrate` on the CLI. It rewrites legacy Motoko into the moc 2.0 brace discipline.

## Facts the design rests on

From the grammar (0.2.0):

- ABI 15, generated by tree-sitter-cli 0.26.10. It loads in `web-tree-sitter` ≥ 0.25. Pin `web-tree-sitter` exactly, starting at 0.26.x.
- The npm package ships `tree-sitter-motoko.wasm` at its root, next to native N-API bindings that have an install script. **We vendor the wasm into our build output and keep the grammar a devDependency**, so plugin users never run `node-gyp-build`.
- There is no external scanner. Whitespace sensitivity comes from `token.immediate`: glued `(`/`[` in heads, glued `<` for type instantiation, and `??` whose token includes one trailing whitespace character.
- **Precedence is flat.** All binary operators sit on one left-associative level, so `1 + 2 * 3` parses as `(1 + 2) * 3`. The printer may never add or remove parens around operators, and it must lay out a binary chain as a flat sequence so the wrong tree shape never shows.
- Legacy and moc 2.0 forms use the same node kinds. They differ in children: a `par_exp` condition, anonymous `(`/`)` in `for`, bare versus `block_exp` bodies, an optional `;` after a case.
- Head-mode nodes are aliased with a `_block`/`_object` suffix (`call_exp_block`, …). The normaliser strips the suffix into a `mode` flag.
- Comments are `extras` and can appear anywhere, even between `f` and `(x)`. `block_comment` nests. Comment text is lexed one character per token, so text is always sliced from source offsets.
- Known deviations from moc: `if g(1) -1 > 0 {}` parses here but moc rejects it, and `if (c) -h {} else {5}` reads as `(c) - h`. That is why moc itself is part of the corpus checks.

From the compiler (`caffeinelabs/motoko`, 2.0.0-beta.1 tagged 2026-09-22):

- 2.0 accepts both syntaxes. Nothing warns on legacy syntax yet. v3 (RFC #6352) removes the legacy forms.
- PR #6385 hand-migrates the compiler's own Motoko to v2. Its rules and its "where the parentheses stay" list are the spec for `moc2`, and its before/after files are a ready test oracle.
- `moc.js` exports `parseMotoko(recovery, src)`, which returns a JSON AST. That is the AST-equivalence oracle, with the normalisation #6385 used: `ParP`, single-expression `BlockE`, and anonymous names that embed positions.
- `func f() : T = e` stays. Rewriting it to a block changes async/shared desugaring.

From the consumers:

- mops pins Prettier 3.5.3 and plugin 0.13.0. It passes `parser: "motoko-tt-parse"` explicitly and copies `wasm/pkg/nodejs/wasm_bg.wasm` into its bundle. Both break on the new plugin, so mops needs a coordinated bump.
- vscode-motoko uses Prettier 2.8.0, sync, in the language server, and formats `.did` with `semi: false`. Both change in M5: it moves to Prettier 3 and stops formatting `.did`.
- The mops toolchain downloads `lintoko-<arch>-<platform>.tar.xz` (for example `aarch64-apple-darwin`). If mo-fmt publishes `mo-fmt-<triple>.tar.xz` with a single top-level directory, the lintoko download code can be copied almost as is.
- Other repos (ai-core-opencode, marketplace-apps, motoko-core, …) use the Prettier CLI with the plugin at 0.8–0.13, and some set `motokoRemoveLinesAroundCodeBlocks`. motoko-training post-processes output with `sed` to fix `??` spacing.

## Target architecture

```
packages/
  prettier-plugin-motoko/          npm: the plugin (ESM only, Prettier 3 peer)
    src/
      index.ts                     languages, parsers, printers, options
      parser/
        tree-sitter.ts             lazy, memoised init of web-tree-sitter + grammar
        parse.ts                   text → CST → normalised tree; ERROR/MISSING → SyntaxError with loc
        normalize.ts               plain objects: type, mode, fields, children incl. tokens, start/end
        nodes.generated.ts         discriminated union generated from node-types.json
      comments/                    attach handlers (ownLine / endOfLine / remaining)
      printer/                     one module per area: dec, exp, control, pat, typ, obj, imports
        adjacency.ts               the whitespace-sensitive token pairs, in one place
      rewrite/moc2/                one module per rewrite rule, each with its own precondition
      verify.ts                    runtime guard: re-parse the output and compare trees
      options.ts
  mo-fmt/                          npm + SEA binaries; depends on the workspace plugin
tools/
  gen-node-types.ts                regenerates nodes.generated.ts from the pinned grammar
  corpus/                          fetch corpus, run checks, churn report
  validate-moc2/                   #6385 oracle, semantic levels, residue scan, divergences.json, report.md
tests/
  format/<area>/*.mo               input fixtures, snapshot output
  rewrite/moc2/<rule>/*.mo
  corpus.test.ts                   gated by an env var, runs in its own CI job
```

Key choices:

- **Prettier stays the layout engine.** Its Doc IR, comment attachment, `printWidth`, `.prettierrc`, overrides and editor integrations are exactly what we need. The plugin is the product and mo-fmt wraps it.
- **Generated node types plus exhaustive `switch` in the printer.** A grammar bump that adds or renames a node fails `tsc`, not a user's format run. The grammar is pinned exactly because minor bumps change tree shape (as #30 did).
- **Adjacency is the safety core.** `adjacency.ts` lists every token pair whose spacing changes meaning, under either moc 1.x or moc 2.0 lexing, and says how to print each one. All other spacing is free. That list covers: glued `(`/`[` after a head expression, glued `<` for instantiation versus spaced `<` for comparison, spaced `??`, `-`/`+`/`^`/`#` after a head (`if (c) -1`), `5.toText()` (no `.` token), and juxtaposition `f x`.
- **The `preserve` invariant: output means the same under moc 1.x and moc 2.0.** Whitespace normalises only where both lexers agree. For example, `a ?? b` always gets its space, because 2.0 requires it and 1.x accepts it. That replaces motoko-training's `sed` hack.
- **Rewrites are tree-to-tree passes before printing.** The printer stays one uniform printer. `verify.ts` compares the output tree with the _rewritten_ input tree, so the guard covers `moc2` too.
- **Semicolons follow the compiler's style guide** (`doc/md/reference/style-guide.md`, as rewritten in #6385):
    - `;` between items is always printed, because the grammar requires it. That includes after a `}`: `if c { … };` followed by another statement.
    - After the last item, `;` is printed only when the block breaks over several lines. A block on one line has none: `case 0 { A }`, `func add(x : Nat, y : Nat) : Nat { return x + y }`. In Prettier terms this is `ifBreak(";")`.
    - The same rule applies to `module`/`actor`/`object`/`class` bodies, record literals, object types and variant types.
    - No `;` between `case` arms, since `case` already ends the previous arm. `moc2` drops it after a braced arm. `preserve` keeps it, because moc 1.x needs it after a bare arm.
    - `semi: false` drops the trailing `;` in broken blocks too, which keeps motoko-core's current style. The default is `true`, the style guide.
    - The trailing `;` never changes meaning: moc's `seplist` gives `{ a; b }` and `{ a; b; }` the same AST (parser.mly:378).
    - This replaces today's guessing from line shape, which appends `;` to any line that is exactly `}`.
- **Candid is out.** `.did` is removed from `languages`, and the motoko.rs lexer goes with the old engine. Nothing in this repo formats or parses Candid.

Options in 1.0:

| option                                                                         | values                       | notes                                                             |
| ------------------------------------------------------------------------------ | ---------------------------- | ----------------------------------------------------------------- |
| `motokoSyntax`                                                                 | `preserve` (default), `moc2` | `moc3` follows once the compiler drops the legacy forms           |
| `motokoOrganizeImports`                                                        | boolean, default false       | reimplemented on `import` nodes, far simpler than today           |
| `motokoRemoveLinesAroundCodeBlocks`                                            | boolean, default false       | kept, because ai-core-opencode sets it                            |
| `semi`, `trailingComma`, `bracketSpacing`, `printWidth`, `tabWidth`, `useTabs` | Prettier standard            | `semi` only controls the trailing `;` in broken blocks, see above |

The parser registers as `motoko`, with `motoko-tt-parse` kept as an alias for one major so the current mops call keeps working. The language gets `aliases: ["mo"]`, which lets Prettier format fenced `motoko` blocks in Markdown docs without extra work.

## Style

Written down in `docs/style.md` before the printers, then reviewed on real diffs of motoko-core and the skills packages. Starting positions, taken from the compiler's style guide and #6385 where they speak:

- 2-space indent, `printWidth` 80. At most one blank line is kept, and none are invented.
- A blank line after the import section, as today.
- Blocks, records and object types: `{ a = 1; b = 2 }` on one line, one item per line with a trailing `;` when broken (see Key choices).
- `switch`: one `case` per line. `case p { e }` hugs when it fits.
- Function signatures break like TypeScript: parameters first, then return type.
- Binary chains break after the operator into one indented run (the tree has no precedence, so no nested groups). `|>` pipelines break before each `|>`.
- Member chains break one call per line past two calls when they don't fit. This is the case the commented-out test wanted.
- Comments are printed verbatim and never converted between `//` and `/* */` (today's printer turns `//` into `/* */` inside `<…>`). A line comment inside a group forces the group to break instead.
- Text, number and char literals are printed verbatim from source.

## The `moc2` rewrite

These are the rules from #6352/#6385 that apply to the 2.0 grammar, listed in the order the passes run. Each rule is a module with a precondition. If the precondition fails, the site is left in its legacy form (still valid on 2.0) and reported.

| rule                  | rewrite                                                                                                           | precondition (skip and report otherwise)                                                                                                                                                                                                              |
| --------------------- | ----------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `brace-bodies`        | bare `if`/`else` branches, `while`/`for`/`loop` bodies, `case`/`catch` arms, `try`/`finally` bodies → `{ e }`     | the body is an expression, not a declaration. `else if` stays a chain.                                                                                                                                                                                |
| `tight-apply`         | everywhere, not only in heads: `f (x)` → `f(x)`, `xs [i]` → `xs[i]`, `f x` → `f(x)`, `f {a = 1}` → `f({ a = 1 })` | the node is a call or index in the tree. A parenthesised or tuple argument is tightened as is: `f (a, b)` → `f(a, b)`. Runs before `unparen-heads`, so a juxtaposed head `if (f x == 0)` becomes `if f(x) == 0 { … }` rather than keeping its parens. |
| `unparen-heads`       | `if (c)` → `if c`, likewise `while`, `switch`, and `for (p in e)` → `for p in e`                                  | the body is braced (by the rule above) and the inner head is not: a tuple, a record, contains `{`, a statement-like form (`:=`, `return`, `let`, …), or an `await` operand of a comparison. The glued `(`/`[` after the head must be the tight form.  |
| `drop-case-semi`      | `case p { … };` → `case p { … }`                                                                                  | the arm is braced                                                                                                                                                                                                                                     |
| `unwrap-case-pattern` | `case (p)` → `case p`, and `case (#tag x)` → `case #tag(x)`                                                       | `p` is in the bare set: `null`, literal, `-1`, `_`, identifier, `(…)`, `{…}`, `?p`, `#tag`, `#tag(p)`. Or-patterns, and-patterns and annotations keep their parens.                                                                                   |
| `coalesce-do`         | `opt ?? { block }` → `opt ?? do { block }`                                                                        | only if corpus work shows legacy code actually contains this. The 0.2.0 grammar may already read it as a record, so verify first.                                                                                                                     |

Not rewritten: `func … = e`, operand-position blocks (`debug {…}`, `label l {…}`, `let … else {…}` → `do {…}`; these are v3, `moc3`), and parens around operators (flat precedence).

Output guarantees for `moc2`, all enforced by tests:

- `format(moc2(x), moc2) == moc2(x)`: the rewrite is idempotent.
- `format(moc2(x), preserve) == moc2(x)`: moc2 output is a fixed point of the default mode.
- The rewritten file type-checks on moc 2.0 whenever the original type-checked on 1.x.

`mo-fmt migrate [paths]` is the tool face: `--syntax moc2 --write`, plus a summary of rewritten sites per rule and of the sites skipped with their reason.

## Verification

Four layers, from cheap to expensive:

1. **Unit fixtures.** `tests/format/**` and `tests/rewrite/**` use Vitest snapshots. Every fixture also asserts idempotence. The 68 formatter tests and 34 organize-imports tests from 0.13 are ported as fixtures. Each is kept, changed on purpose (with a note), or deleted as a bug.
2. **Runtime guard** (`verify.ts`, always on, no opt-out). **A failure throws.** The format errors with the first differing node and its location, and never writes output. Re-parse the output. It must contain no `ERROR`/`MISSING`. Its normalised tree (types, fields, token texts) must equal the input tree, or the rewritten tree for `moc2`. The comment texts must match in order. Prettier's own "comment was not printed" check covers dropped comments.
3. **Corpus job** (CI, own job): `../motoko/test`, motoko-core, the grammar's `test/packages.json` set, plus skills-internal and mops-packages locally, since they are private. For every file, in both modes:
    - token round-trip: re-concatenating tokens and gaps reproduces the input. This proves the normaliser loses nothing.
    - idempotence, the re-parse check, and the tree-equality check;
    - `moc.js parseMotoko` AST equality between input and output, normalised as #6385 did. The oracle is moc, not our grammar, which catches the grammar's deviations.
    - `moc2` only: see the next section.
4. **Compile check** (nightly or manual). For corpus packages with a `mops.toml`, `mops check` on moc 2.0 beta, before and after `moc2`.

Plus a **churn report**: 0.13.0 (installed as `npm:prettier-plugin-motoko@0.13.0`) against the new engine on the corpus. The diff is reviewed per construct before the beta. It is the evidence the style is right and the parity gap is closed.

## Validating `moc2` on the compiler repo against #6385

`moc2` ships only after two things are proven on real code:

1. **Safety.** It never produces invalid code and never changes semantics.
2. **Coverage.** It reaches the target syntax of moc v2, measured against the compiler team's hand migration in caffeinelabs/motoko#6385.

The harness lives in `tools/validate-moc2/` and runs in a CI job. It pins two compiler revisions: the merge base of #6385 (**base**) and its head, `1d57a4fc` (**head**). A new push to #6385, or its merge, is adopted by re-pinning on purpose, never by following a branch.

### Units

A unit is either a `.mo` file or a parseable `motoko` fence in a Markdown file. #6385 counted 338 units in the files it touches. The harness uses the same unit definition over two sets:

- **The oracle set**: exactly the files #6385 touches (`doc/md/**`, `doc/overview-slides.md`, `samples/**`, `src/prelude/**`), read at base.
- **The full set**: every `.mo` and fence in the motoko repo at base, including `test/**`. #6385 left `test/**` alone because it "wants the formatter first".

Fences are extracted wherever they sit, including when they are indented inside list items. #6385's own first harness anchored the fence regex at column 0, silently matched none of `style-guide.md`'s fences, and so skipped the file with the largest diff. So the harness also asserts **expected unit counts** per file and fails when a count drops.

Units that can't be checked are counted and listed, never dropped quietly:

- `src/prelude/*.mo` uses `@`-privileged names, and the grammar can't reach `privileged_identifier`. It is checked by rebuilding moc and diffing the IR of a driver, the way #6385 did, once the grammar gap is fixed. Until then it is out of the numbers and filed as a grammar issue.
- Units that don't parse on base are recorded as `pre-existing failure` (for example `doc/schat.mo`).

### Goal 1: never invalid, never a semantic change

Every unit in the full set is rewritten with `moc2`. Each output must pass every level below; a failure at any level is a bug, with no allowlist.

| level       | check                                                                                                                                                                                                                                                                                                                                                                         |
| ----------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| parse       | the output parses under moc 2.0, both the pinned beta release and moc.js built from master, since #6388 changed what heads accept after beta.1. Our grammar parses it with no `ERROR`/`MISSING` nodes.                                                                                                                                                                        |
| diagnostics | `moc --check` on output gives the same diagnostic codes, with the same count per code, as on input. No new error or warning, `unused identifier` included. Units under `test/fail` must fail with the same codes as before.                                                                                                                                                   |
| parse tree  | `moc -dp` (or `parseMotoko`) of input and output are identical after normalisation. **Normalisation only forgives differences at sites in the rewrite's edit log**: a `ParP` it unwrapped, a single-expression `BlockE` it added, a `;` it dropped. Anonymous-function names carrying source positions are normalised everywhere. Any difference outside a logged site fails. |
| typed tree  | `moc -dt` agrees under the same normalisation. This catches rewrites that parse the same but resolve differently.                                                                                                                                                                                                                                                             |
| execution   | the compiler's `test/run` (309 tests) and `test/run-drun` (439 tests) run on the rewritten tree. Their stdout and trap output match the goldens exactly. Golden diffs may only differ in line/column ranges, and a filter checks that nothing else moved. This runs in a nix shell of the motoko repo, nightly or on demand, not on every PR.                                 |
| idempotence | `moc2(moc2(x)) == moc2(x)`, and `preserve(moc2(x)) == moc2(x)`                                                                                                                                                                                                                                                                                                                |

**The harness proves it can fail.** A self-test plants known-bad rewrites into a copy of the corpus and requires each level to catch them. The planted rewrites are:

- dropping the parens of a juxtaposed-application head: `if (f x == 0) a` → `if f x == 0 { a }`, the silent misparse #6385 found;
- dropping the parens of an `await` comparison head;
- bracing a `func … = e` body;
- unwrapping `case (a or b)`.

A level that lets any of these through is itself a bug. This guards against a harness that passes because it checks nothing.

### Goal 2: coverage of the v2 target syntax

The oracle set is compared with #6385's head, **per unit and at tree level**. First, our output and head are each run through `preserve`, so layout never counts as a difference. Then they are parsed with our grammar and compared node by node.

- **Match**: identical tree. This is the metric that is reported and tracked.
- **Every mismatch lands in one of three buckets** in `tools/validate-moc2/divergences.json`. Each entry names the unit, the site and a one-line reason. CI fails on any mismatch not listed there.
    - **Missed**: #6385 rewrote a site we left. This is a coverage gap, fixed with a new rule or a relaxed precondition. The entry is temporary and must be empty before `moc2` leaves beta.
    - **Extra**: we rewrote a site #6385 left. We check the site is valid under Goal 1. Then it is either reported upstream as a site the hand migration missed, or reclassified as a precondition we got wrong.
    - **Intended**: an edit that isn't syntax migration. Examples are `style-guide.md`'s deliberate `// COUNTER EXAMPLES!` legacy block, the prose-driven `func` wrappers #6385 added around undeclared names, and `func … = e`, which both sides leave alone. These stay listed permanently.

**Residue scan on the full set.** A legacy scanner walks our tree and counts every construct the v2 target retires:

- parenthesised heads;
- bare `if`/loop bodies and bare `case`/`catch` arms;
- `;` after a braced arm;
- whole-pattern parens on a single case pattern;
- spaced application or indexing.

#6385 measured 549 bare arm bodies and 1249 arm separators under `test/**` alone. After `moc2`, **every remaining site must appear in the skip report with its precondition**. That covers, for instance:

- tuple and record heads, and heads containing `{`;
- the `await` operand of a comparison.

Every skip reason must match one on #6385's "where the parentheses stay" list or have an entry in `divergences.json`. The target is zero unexplained residue.

**Report.** Each run writes `tools/validate-moc2/report.md` with:

- units checked and units skipped, with reasons;
- the tree-match rate against head, and the bucket counts;
- sites rewritten per rule, and residue per construct;
- the Goal 1 status per level.

The report is attached to the M3 release notes.

### What it hands back

When both goals are green on the full set, the harness output doubles as the remaining sweep #6385 deferred. `mo-fmt migrate` over the motoko repo's `test/**`, with goldens regenerated, becomes a PR to caffeinelabs/motoko (M5).

## Tooling reset

The old engine is not kept alive on `main`:

- Cut `release/0.13` from today's `main` for critical fixes only.
- Delete the Rust crate and its `motoko` (motoko.rs) dependency, wasm-pack, `wasm/`, the Prettier 2 parse overload, the `.did` language entry, the rollup config, `npm-run-all`, `rimraf`, ts-jest and Jest. The ts-jest pin is what capped TypeScript below 7.
- ESM-only TypeScript, built with `tsc` to `dist/`, plus a copy step for the two wasm files (grammar and `web-tree-sitter`). Node ≥ 22 at runtime.
- Vitest for tests.
- npm workspaces at the root. CI (Node 22/24) runs `typecheck`, `format:check`, `test`, `test:web` and `corpus`. The web job runs a Vite build _and_ formats a snippet in a headless browser, instead of only building.
- Repo metadata points at `caffeinelabs/prettier-plugin-motoko`, not dfinity.
- Keep `min-release-age=7` in `.npmrc`. Grammar 0.2.0 was published 2026-09-23, so it resolves from 2026-09-30. Until then, develop against `file:../tree-sitter-motoko` with the wasm rebuilt from `v0.2.0` (the local `tree-sitter-motoko.wasm` predates PR #25).

## mo-fmt

- Lives in `packages/mo-fmt` and depends on the workspace plugin plus Prettier 3, bundled with esbuild into a single CJS file for SEA.
- CLI:
    - `mo-fmt [paths…]`: write in place. `.mo` files only.
    - `--check`: exit 1 when a file would change.
    - `--stdin-filepath <p>`: read stdin, write stdout. Editors call it this way.
    - `--syntax preserve|moc2`, which overrides config.
    - `migrate` subcommand.
- Config: resolved per file with `resolveConfig(file, { editorconfig: true })`, and `.prettierignore` is honoured. Both are gaps in mops today.
- Binaries: Node SEA, built natively on `ubuntu-24.04`, `ubuntu-24.04-arm`, `macos-15` and `macos-15-intel`. The wasm files go in as SEA assets. Assets are named `mo-fmt-{x86_64,aarch64}-{unknown-linux-gnu,apple-darwin}.tar.xz`, lintoko-style. Every build job smoke-tests its binary by formatting and `--check`-ing a fixture.
- Release: a tag push `v*` publishes the plugin and mo-fmt to npm (trusted publishing with provenance, like the grammar repo) and the binaries to the GitHub release. A pre-release version goes to the `next` dist-tag. The plugin and mo-fmt share one version, checked in CI.

## Versioning

- The new engine is **1.0.0**: Prettier 3 only, ESM, parse errors fail, output changes. Betas `1.0.0-beta.N` go on `next`.
- While moc 2.0 is in beta, the `moc2` rewrite may change between minors. That is documented in the option's description.
- The default flips to `moc2` as **2.0.0**, when moc 2.0 is the default toolchain in mops.

## Milestones and PRs

Each milestone ends in something shippable or measurable.

**M0: spike (scratch branch, not merged)**

- Load grammar 0.2.0 with `web-tree-sitter` in Node, in a Vite browser build and inside a Node SEA binary. Parse motoko-core. Measure init and parse time.

**M2: preserve printer at parity**

**M3: moc2 rewrite**

## Decided

- Prettier 3 only. vscode-motoko moves to Prettier 3.
- No `.did` support, no motoko.rs.
- Semicolons: always between items, trailing only when the block breaks (the compiler's style guide). No `;` between `case` arms in `moc2`.
- `tight-apply` applies everywhere: `f x` → `f(x)`.
- The runtime guard throws.

Out of scope, as before: fixing precedence in the grammar, the `= e` function body, and v3 (`moc3`) rewrites.
